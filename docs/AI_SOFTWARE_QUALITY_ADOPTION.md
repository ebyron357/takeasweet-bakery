# AI Software Quality & Security — Project Adoption

Canonical governing standard: https://github.com/ebyron357/AI-Operating-Standards/blob/main/docs/AI_SOFTWARE_QUALITY_SECURITY_MASTER_STANDARD.md

## Mandatory checklist (verify against actual implementation)
- [ ] Visual consistency: typography, spacing, colors, gradients, shadows, cards and branding.
- [ ] Code hygiene: duplicate components, unused imports, dead routes, conflicting CSS, obsolete packages and AI-generated debris.
- [ ] Functional UI: no dead controls, fake charts, fabricated testimonials, production mock data, nonfunctional settings or false success messages.
- [ ] Responsive design and accessibility: mobile navigation, dialogs, tables, tap targets, keyboard, labels, contrast, WCAG 2.2 AA evaluation.
- [ ] Security: secret scanning, least-privilege server-side authorization, tenant isolation, safe rendering, protected uploads and APIs.
- [ ] Backend: persistence, validation, migrations, data integrity, backups, restore and observability.
- [ ] Integrations: real APIs, OAuth scopes, webhook signatures, retries and recovery.
- [ ] Agent controls where applicable: identity, supervisor, tool scope, approvals, tracing, revocation, JEV and owner override.
- [ ] Performance and discovery: Core Web Vitals, SEO, GEO, AEO, structured data, no deceptive injection.
- [ ] Privacy and compliance: scoped HIPAA/NIST/government requirements and evidence; never claim certification without proof.
- [ ] Testing and release: lint, build, unit, E2E, accessibility, visual regression, security, CI, rollback and owner approval.
- [ ] Documentation: architecture, owners, inventory, audit evidence and current governing standard.

## Execution protocol
Inventory and verify first. Record severity P0-P3, evidence, reproduction, root cause, fix, tests and approval. Do not invent blockers or passing checks. Preserve working systems and data. Make repairs in reviewable branches; owner controls production release.
